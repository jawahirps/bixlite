# BIX Lite — application workspace redesign
A new app-style visual shell, rather than a worksheet: grouped icon sidebar, compact command search, assigned account chip, five financial cards, chart/status grid, context filters, and actual claim lifecycle worklist. Desktop and phone reflow. No C-level/analyst/SME selector, tenant selector, or subscription picker in the user-facing application. Assigned profile determines layout automatically; entitlement administration/test fixture is separate.
## Interaction design
Press and hold a widget for ~0.48 seconds to enter editing; drag its move grip to reorder within the semantic group, drag resizing grip for live compact/standard/expanded snapping, or use keyboard arrows and +/−. Done commits layout locally per assigned preview profile; Cancel or Escape restores previous state. The edit dock is visible only during edit. Display menu provides an accessible alternative to long press. Reset is available in editing. Mobile dimensions reflow, and chart/table scrolling stays inside the relevant panels.
All approved reporting functions retained: Five mutually exclusive financial allocations, meaningful grouped bar/month drill, shared saved checkbox/select-all filters with reversible year/month/day calendar, profile-based module/capability gates, evidence and resubmission cycles, draft-only reconciliation, session timer, 17 existing navigation destinations (non-dashboard module routes are illustrative).
## Verification
Eight synthetic acceptance groups passed in `regress.cjs`; widget mock tests passed. Actual Chromium desktop render verified. Long-pressed Paid card, dragged it after Denied, dragged resize handle to broaden Paid (201px→414px), saved with Done, reload restored both order and size. Actual 390px iframe rendered; pointer long press opened edit, Reset restored four KPIs, Done saved and hid handles. Phone rendering and mouse/pointer gesture checked, not a physical touchscreen. Earlier lifecycle workspace verified tenant-scope, persisted multi-select, dates and second rejection draft; all regression checks retained.
## Scope
Demo data only, no production deployment, actual authentication, subscription, payment, portal credentials, or clinical claim activity. Fixed assigned preview profile stands in for future server-validated session identity; separate admin/test fixture demonstrates entitlements, not an actual login/billing system. Production must implement server-side tenant/permission/facility controls and user-specific preference persistence, source-backed financial calculations, authorized review and audit. The application is self-contained HTML/JS, not a React framework build.
